    ## Node.js问题解决方法论
    
    ### 问题分类体系
    - **运行时错误**：内存泄漏、崩溃、性能瓶颈
    - **网络问题**：连接超时、DNS解析、SSL证书
    - **数据库问题**：连接池耗尽、查询性能、事务处理
    - **并发问题**：竞态条件、死锁、资源竞争
    - **部署问题**：环境差异、依赖冲突、启动失败
    
    ### 调试技术栈
    - **Chrome DevTools**：性能分析、内存快照、堆栈跟踪
    - **Node.js Inspector**：--inspect模式、断点调试
    - **日志分析**：Winston、Morgan、ELK Stack
    - **监控工具**：Prometheus、Grafana、New Relic
    - **APM工具**：Sentry、Datadog、AppDynamics
    
    ### 故障排查流程
    - **复现问题**：稳定复现环境、最小化用例
    - **信息收集**：日志、错误堆栈、系统资源
    - **根因分析**：层次分析法、排除法、假设验证
    - **解决方案**：短期修复、长期优化、预防措施
    - **验证测试**：回归测试、性能测试、压力测试
  </exploration>
  
  <challenge>
    ## 问题解决挑战检验
    
    ### 复杂问题挑战
    - **分布式系统**：跨服务调用、网络延迟、数据一致性
    - **高并发场景**：限流策略、降级方案、熔断机制
    - **性能瓶颈**：CPU密集型、I/O密集型、内存密集型
    - **安全漏洞**：XSS、CSRF、SQL注入、权限提升
    
    ### 技术债务挑战
    - **代码重构**：模块拆分、接口优化、算法改进
    - **技术升级**：Node.js版本迁移、依赖包更新
    - **架构重构**：微服务化、事件驱动、响应式设计
    - **基础设施**：容器化、云原生、DevOps转型
    
    ### 团队协作挑战
    - **知识共享**：技术文档、代码审查、培训体系
    - **项目管理**：敏捷开发、里程碑规划、风险管理
    - **质量保障**：测试策略、发布流程、回滚机制
    - **持续改进**：性能监控、用户体验、技术指标
  </challenge>
  
  <reasoning>
    ## 问题解决推理框架
    
    ### 问题诊断决策树
    ```
    问题描述 → 错误分类 → 技术栈分析 → 可能原因 → 验证假设
    ```
    
    ### 系统化思维方法
    - **分层分析**：基础设施层、应用层、业务层、用户层
    - **时空分析**：时间维度（启动、运行、停止）、空间维度（单机、集群、分布式）
    - **关联分析**：服务依赖、数据流、调用链路
    
    ### 解决方案评估标准
    - **可行性**：技术难度、时间成本、资源需求
    - **有效性**：解决问题程度、副作用影响
    - **可维护性**：代码质量、文档完整性、团队技能匹配
    - **扩展性**：未来需求、性能要求、架构适应性
  </reasoning>
